# دليل المالك: ضَجّة مول

هذا الملف لك أنت فقط، لا ترفعه إلى GitHub (يذكر أشياء أزلتها من المشروع).

---

## 1) ما الذي تغيّر في المشروع

**الأمان والسيرفر**
- مسار المساعد صار `/api/assistant` (بدل `/api/gemini/assistant`) وأُزيل ترويس `aistudio-build`.
- حد للطلبات لكل IP (120 رسالة للمساعد، 40 للبحث بالصورة، كل 10 دقائق)، وحدود لحجم الطلب والنصوص والكتالوج.
- CORS محدد: نفس الموقع، وتطبيق الجوال (`https://localhost`)، وما تضيفه في `ALLOWED_ORIGINS`. أي موقع آخر يُرفض (403).
- كود السيرفر لم يعد يُشحن داخل الـ APK (كان `server.cjs` وملف الـ sourcemap داخله). صار يُبنى في `server-dist/` خارج الحزمة.

**الواجهة**
- المساعد والبحث بالصورة يقرآن رابط السيرفر من `VITE_API_BASE_URL` (كانا يستدعيان مساراً نسبياً لا يعمل داخل الـ APK).
- أُزيل المندوب الوهمي (عمار الحميدي ورقمه) الذي كان يُضاف لكل طلب. قسم المندوب لا يظهر إلا لو وُجدت بيانات حقيقية. ونص الخريطة صار يقول أن الموقع تقريبي.
- أُزيل الإيموجي الزخرفية من النصوص، وأُزيلت كل التعليقات (1,300+) من الكود، وبُدلت صياغات "AI" الظاهرة بـ "المساعد الذكي".
- السماح بالتكبير (كان معطلاً)، مع منع التكبير بالنقر المزدوج.

**متطلبات المتاجر (جديد)**
- حذف الحساب من داخل التطبيق: الإعدادات ← "حذف حسابي وبياناتي نهائياً".
- زر "إبلاغ عن رد غير مناسب" تحت كل رد من المساعد (يُحفظ في مجموعة `aiReports`، وتراجعها من Firebase Console).
- صفحتا الخصوصية وحذف الحساب: `/privacy.html` و`/delete-account.html`.
- زر Google أُخفي داخل التطبيق (انظر القسم 6).
- زر "إبلاغ" على كل تقييم (يُحفظ في `reviewReports`).

**المساعد والكوبونات والتخزين (آخر تحديث)**
- المساعد صار يرشّح من منتجاتك الحية (أول 300 منتج متوفر) بدل الكتالوج الثابت.
- الكوبونات صارت تُحفظ في Firestore وتصل لكل العملاء، وتاريخ الانتهاء صار يُطبَّق. وأُزيل الرجوع الخفي لكوبونات الكود التجريبية (DAJJAH10 وYEMEN2026 وFREE_DELIVERY): لو حذفتها من الأدمن لن تعمل. أول ما تدخل كأدمن تُرفع كوبوناتك الحالية تلقائياً إلى Firestore إن كانت المجموعة فارغة، فراجعها واحذف التجريبية.
- ملف `storage.rules` جديد: رفع الصور للأدمن فقط (صور فقط، حتى 8MB) والقراءة للجميع.

**أندرويد**
- أُغلق `cleartext` و`allowBackup`، وأُضيف `uses-feature` اختياري للموقع.
- ملف `android-release.yml` يبني AAB موقّعاً لـ Google Play، ورقم الإصدار يزيد تلقائياً.
- `targetSdk` هو 36 أصلاً.

**قواعد Firestore**
- الطلب لا يُقبل إلا بحالة `received` وبحد أقصى 100 منتج.
- `admins` و`coupons` و`aiKnowledge` و`analytics` للأدمن فقط (الواجهة لا تستخدمها أصلاً).
- المستخدم يقدر يحذف ملفه (لازم لحذف الحساب).
- أُزيل المقطع الأخير `match /{document=**}` لأنه كان بلا أثر ويوحي بحماية غير موجودة.

**ملاحظة تصحيحية:** في فحصي الأول قلت أن الكوبونات مكشوفة في Firestore. الصحيح أن الكوبونات لا تُحفظ في Firestore أصلاً (انظر القسم 6).

## 2) الرفع إلى GitHub

1. فرع جديد من الريبو: `cleanup`.
2. احذف محتوى الريبو القديم (ما عدا مجلد `.git`) وفك ZIP المشروع مكانه.
3. `git add -A && git commit -m "Update project" && git push`
4. افتح Pull Request ودمجه في `main` بعد المراجعة.
5. **توقف عن التعديل من AI Studio** بعد هذا. لو رجعت له قد يعيد ملفاته ويكتب فوق تعديلاتي.

تاريخ الـ commits القديم في GitHub قد يحتوي رسائل من AI Studio. لو يهمك، أنشئ ريبو جديداً وارفع النسخة النظيفة كأول commit.

## 3) خطوات لازم تنفذها أنت (بالترتيب)

1. **انشر الخادم** (Cloud Run مثلاً): أمر البناء `npm run build` وأمر التشغيل `npm start`، وأضف السر `GEMINI_API_KEY`. جرّب `https://رابطك/api/health`.
2. **متغير GitHub:** Settings ← Secrets and variables ← Actions ← Variables ← `API_BASE_URL` = رابط الخادم https بدون `/` في النهاية.
3. **بريد التواصل:** استبدل `{{CONTACT_EMAIL}}` في `public/privacy.html` و`public/delete-account.html`. (بناء الإصدار يفشل عمداً إذا بقي).
4. **قواعد Firestore:** `npm i -g firebase-tools && firebase login && firebase deploy --only firestore,storage`. تأكد أن اسم قاعدة البيانات في `firebase.json` مطابق لقاعدتك.
5. **Firebase Console ← Authentication ← Settings ← Authorized domains:** أضف دومين الخادم. وتأكد أن مزود البريد/كلمة المرور مفعّل.
6. **قيّد مفتاح Firebase API** في Google Cloud Console ← APIs & Services ← Credentials. أضف المواقع المسموحة: دومينك و`https://localhost/*` (للتطبيق). جرّب التطبيق بعدها قبل النشر.
7. **رقم واتساب الدعم:** الرقم الافتراضي في الكود تجريبي (`967777123456`). تأكد أنه يتغير من إعدادات لوحة الأدمن، وأن بيانات التواصل الحقيقية محفوظة.
8. **كتالوج حقيقي:** لو Firestore فارغ يعرض التطبيق منتجات تجريبية بصور Unsplash وتقييمات وهمية. هذا قد يسبب رفضاً (محتوى مضلل). أضف منتجاتك الحقيقية قبل التقديم.
9. **مفتاح التوقيع:** اتبع `ANDROID_BUILD_GUIDE.md`. احتفظ بنسخة من ملف `.jks` وكلمات المرور في مكانين، فقدانه يعني عدم القدرة على تحديث التطبيق.

## 4) Google Play

**جاهز في الكود:** AAB موقّع، targetSdk 36، حذف الحساب داخل التطبيق + صفحة ويب، سياسة الخصوصية، إبلاغ عن ردود المساعد، بدون HTTP غير مشفر.

**في Play Console:**
- رابط الخصوصية: `https://رابطك/privacy.html`
- رابط حذف الحساب: `https://رابطك/delete-account.html`
- **App access:** أنشئ حساب اختبار (إيميل وكلمة مرور) وضعه في بيانات المراجعة، لأن الطلب يتطلب تسجيل دخول.
- **Data safety:**

| البيانات | تُجمع | ملاحظة |
| --- | --- | --- |
| الاسم، الإيميل، الهاتف | نعم | لإنشاء الحساب والتوصيل |
| العنوان والموقع | نعم | الموقع اختياري |
| سجل الطلبات | نعم | |
| الصور | نعم | للبحث بالصورة، تُعالج ولا تُخزَّن |
| رسائل المساعد | نعم | |
| تشفير أثناء النقل | نعم | HTTPS |
| طلب حذف البيانات | نعم | داخل التطبيق + رابط الويب |

- **الإعلانات:** لا يوجد. **الدفع:** منتجات مادية، لا حاجة لـ Play Billing.
- إن كان حساب المطوّر شخصياً وجديداً فقد يُشترط اختبار مغلق بعدد محدد من المختبرين لعدد أيام قبل الإنتاج. راجع Play Console.
- الأصول المطلوبة: أيقونة 512×512، صورة مميزة 1024×500، لقطتا شاشة على الأقل، وصف لا يحتوي ادعاءات غير حقيقية.

## 5) App Store (آبل)

**الواقع:** لا يوجد مشروع iOS في الحزمة، وبناؤه يحتاج جهاز Mac وحساب Apple Developer. لا أستطيع بناءه أو اختباره من هنا.

على الـ Mac:
```bash
npm i @capacitor/ios
npm run build:web
npx cap add ios && npx cap sync ios && npx cap open ios
```

نقاط المراجعة وحالتها:
- **حذف الحساب داخل التطبيق:** جاهز.
- **تسجيل الدخول الاجتماعي (4.8):** أُخفي زر Google داخل التطبيق، فالدخول بالبريد فقط، وهذا لا يستوجب "Sign in with Apple".
- **الخصوصية:** عبّئ App Privacy في App Store Connect بنفس جدول Data safety أعلاه. لا تتبع إعلاني ولا حاجة لـ ATT.
- **أذونات Info.plist:** أضف `NSLocationWhenInUseUsageDescription` ونصوص الكاميرا/الصور (للبحث بالصورة)، بالعربية.
- **التقييمات (1.2):** أُضيف زر إبلاغ لكل تقييم، والتقييمات محصورة بالمشترين الموثقين. راجع بلاغات `reviewReports` و`aiReports` دورياً من Firebase Console، وآبل تتوقع الرد على البلاغات خلال 24 ساعة.
- **الحد الأدنى من الوظائف (4.2):** آبل ترفض أحياناً التطبيقات التي تبدو كموقع داخل غلاف. لتقليل الخطر أضف ميزات أصلية (إشعارات Push، مشاركة أصلية) وقدّم حساب اختبار وشرحاً واضحاً.
- لا أستطيع ضمان القبول، فالقرار النهائي عند المراجِع.

## 6) أشياء لم أغيّرها أو لا أستطيع الجزم بها

- **اسم قاعدة البيانات** في ملف الإعدادات `ai-studio-…` وهو مضمّن في كود التطبيق، وهو الأثر الوحيد المتبقي للمنصة. تغييره يتطلب إنشاء قاعدة Firestore جديدة ونقل البيانات (`gcloud firestore export/import`) ثم تعديل `src/config/firebase.config.json` و`firebase.json`. أخبرني لو تريد خطوات مفصلة.
- **تسجيل Google داخل التطبيق:** Google تمنعه داخل WebView، لذلك أُخفي. لإرجاعه تحتاج إضافة `@capacitor-firebase/authentication` (تسجيل أصلي).
- **الكوبونات** صارت تُقرأ من Firestore وهي مقروءة للجميع (الأكواد ليست سرية)، والتحقق منها يتم في جهاز العميل. لا تستخدمها لأكواد خاصة بعميل واحد أو بحد استخدام.
- **إجمالي الطلب** يُحسب في جهاز العميل. تحتاج Cloud Function تعيد حسابه من أسعار Firestore قبل اعتماد الطلب.
- **المساعد الذكي:** نصوص السياسات داخل تعليماته (مثل الإرجاع والتوصيل) مكتوبة في `server.ts`. تأكد أنها تطابق سياساتك الفعلية، أو عدّلها من لوحة الأدمن (تعليمات المساعد).
- **رفع الصور (Storage):** يُسمح للأدمن بإيميل المالك الموثّق (أو صلاحية `admin`/`role` في التوكن). أدمن آخر مضاف من Firestore فقط لن يستطيع الرفع، لأن قواعد Storage لا تقرأ قاعدتك المسماة.
- **الألوان والتصميم:** لم أغيّرهما. لا أستطيع معاينة الشاشات هنا، وتغيير الهوية البصرية دون رؤية النتيجة مخاطرة. أرسل لقطات شاشة وأحدد لك لوحة ألوان وتعديلات دقيقة.
- **لم أشغّل التطبيق على جهاز أندرويد**، ولم يُبنَ Gradle في بيئتي. أعدادات التوقيع في `build.gradle` والـ workflow غير مختبرة. شغّل APK التجريبي أولاً.
- قواعد Firestore لم تُختبر بمحاكي Firebase، فجرّب الطلب والتسجيل وحذف الحساب بعد نشرها.

## 7) ما اختبرته فعلاً

- `tsc` بدون أخطاء، وبناء الواجهة والخادم ينجح من نسخة نظيفة من الـ ZIP.
- بعد حذف التعليقات، ناتج البناء مطابق للأصل (ما عدا ملف CSS فقد صنفاً كان في تعليق).
- السيرفر الحقيقي: المسارات الجديدة، رفض المسار القديم، 400 للمدخلات الخاطئة، 413 للحجم الزائد، 429 بعد حد الطلبات، CORS للتطبيق (يُقبل) ولموقع غريب (يُرفض 403)، وتقديم صفحتي الخصوصية.
- `cap sync` وفحص الأصول: لا ملفات سيرفر ولا sourcemaps داخل أصول الأندرويد، ورابط الخادم مضمّن.
- البحث في الحزمة النهائية عن آثار المنصة: لا شيء عدا اسم قاعدة البيانات.
